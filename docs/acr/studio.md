It is generated from `apps/studio/audit/audit.ts`, where every criterion names its evidence: tests (a name alone is a file in `apps/studio/test/`, a path is from the repository's root; a test checks they exist; they run on every change, except the NVDA screen-reader tests, which run on request on Windows and last ran on 2026-11-08), Guard on every view, and reviews by a person. :::callout[What the results rest on]{variant=note}
Supports means the criterion is met in the combinations tested: Chrome on Windows with the keyboard alone, NVDA in English and Czech, forced colours, zoom and reflow, and touch emulation; Firefox and WebKit by smoke tests. Not tested: JAWS, Narrator, VoiceOver on macOS and iOS, TalkBack, speech input (Dragon, Voice Access), Safari on a Mac and real phones and tablets. The known limits below say the same.

A person last reviewed the Studio on 2026-10-05, before the 2.0.3 layout (the modes, the panes, Present, the phone's bottom bar and the block bar). The views new in 2.0.3 are covered by the automated checks on every change (axe-core and Guard on every view, keyboard flows, reflow, forced colours, touch) and by the NVDA flows of 2026-11-08; no person has reviewed those views. Evidence marked "review" is that review of 2026-10-05.
:::

## Scope

LibKa Studio as built by `node apps/studio/build.mjs` and served by `libka studio`: the library, the visual, source and split editors, the modes (Write, Blocks, Focus), the left pane (Catalog, Outline), the companion pane (Preview, Checks with the source's problems and Guard's findings in one list, Properties, Versions), Present, the command palette, menus and dialogs, Preferences, the tour and the tutorial, in English and Czech, light, dark, high contrast and forced colours, at desktop, tablet and phone width. Tested in Chrome on Windows, with Firefox and WebKit smoke tests. The Studio is a web application, so EN 301 549 clause 9 applies; clause 11.8 is added because it is an authoring tool. Clause 12 (documentation and support services) is not evaluated in this report.

## Known limits

- Screen readers: NVDA with Chrome on Windows is tested; VoiceOver on macOS and iOS, JAWS and Narrator are not.
- Firefox and Safari (WebKit) are covered by smoke tests (editing in both modes), not by the full suite.
- Touch is tested with touch emulation in Chrome, not on real phones and tablets.
- Problem messages from the document checks are in English in the Czech interface, marked as English for screen readers (their fixes and explanations are in both languages).

## How it was evaluated

Automated, on every change: axe-core 4 with the WCAG 2.0, 2.1 and 2.2 A/AA rules and Guard's contrast and structure rules on every view of the Studio (standard and high contrast, light and dark, forced colours); keyboard-only flows; reflow, text spacing, focus visibility and field contrast checks; the performance budget. With a screen reader: NVDA driven by tests in English and Czech (run on request on Windows: `LIBKA_SCREEN_READER=1`; last run on 2026-11-08, both flows passed). By a person: each review named in the evidence, last done on 2026-10-05, before the 2.0.3 layout. The views new in 2.0.3 (the modes Write, Blocks and Focus, the panes, Present, the phone's bottom bar and the block bar) are covered by the automated checks above and the NVDA flows of 2026-11-08; no person has reviewed those views.
