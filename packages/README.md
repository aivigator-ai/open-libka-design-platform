# LibKa packages (TypeScript workspace)

pnpm workspace, strict TypeScript, Vitest. Node runs the TypeScript sources directly (type stripping, Node 22.18 or newer). The token files are generated by the Python build (`generate.py`).

| Package | Purpose |
|---|---|
| `blocks` | The block registry: syntax, attributes, JSON schema, accessibility rules, anti-patterns and per-output behaviour of every block; its Czech names, summaries and help for editors (`i18n.ts`); what to write for content without a block (`fallbacks.ts`); generators for the catalog (`docs/blocks.md`) and the skill reference |
| `model` | Markdown with directives to typed blocks; problems reported by line, each with a code and, where safe, fixes (`Fix`); a sample document per code (`samples.ts`) and the generator of `docs/problem-codes.md` (`build-codes.ts`) |
| `render` | Self-contained web pages and decks from the blocks and tokens: charts, diagrams, slide fitting (`@libka/render/fit`, shared with the Studio), a strict hash-based Content Security Policy (`@libka/render/csp`), Czech typography |
| `guard` | Checks rendered pages in headless Chrome: axe-core WCAG 2.2 A/AA, live text contrast in standard and more-contrast modes, structure rules (reflow at 320 CSS pixels among them), blocked-by-policy content. Checks Word files' structure and contrast (`@libka/guard/docx`, browser-safe). Also the WCAG 2.2 / EN 301 549 mapping and conformance reports (`@libka/guard/wcag`, `build-acr.ts`), and the Ed25519-signed manifest of the checks (`@libka/guard/manifest`) |
| `pdf` | Makes Chrome's tagged PDFs meet PDF/UA-1 (metadata, role map, figure groups, list bodies, link descriptions, artifacts) and runs veraPDF (`@libka/pdf/verapdf`); see `docs/admin/verapdf.md` |
| `docx` | The editable Word file: Word headings, lists, footnotes, tables with repeating header rows, pictures with alternative text, styles from the tokens (`theme.ts`, generated by `generate.py`); byte-identical builds; browser-safe, so the Studio uses it too. `@libka/docx/libreoffice` converts with LibreOffice for the proof that a file opens; `scripts/word-check.ps1` opens files in Word. See `docs/admin/word-and-libreoffice.md` |
| `editor` | Visual editing of LibKa documents: the ProseMirror schema; Markdown to the editor and back with every untouched block byte for byte and changed blocks in one canonical style (`load`, `save`, `saveMapped`); block names, settings and their help from the registry in English or Czech, and search in both (`names.ts`); the block commands (select, move, duplicate, delete, change type, wrap, insert, Markdown on the clipboard, Markdown shortcuts); a problem's fixes applied to the text (`applyFix`). Browser-safe; its tests round-trip every document in the repository |
| `cli` | `libka build <file.md> [--out <dir>] [--outputs web,pdf,deck,docx] [--pdf] [--deck] [--docx] [--no-check]` (by default what the front matter `outputs` asks for), `libka lint <file.md> [--json]`, `libka check <page.html>`, `libka verify <page.html> [--pdf <file>] [--docx <file>] [--require-trusted]` (`--require-trusted` fails when the signing key is not trusted), `libka studio [--port <n>] [--dir <folder>]` (serves the built Studio on localhost), `libka doctor`, `libka --version`; `src/assets.ts` finds the shipped files and a document's project (its `.libka/` key and trusted keys). Published as `@libka/cli` with the engine bundled (`npm/build.mts`) |
| `mcp` | The MCP server for AI agents: list and describe blocks, check LibKa Markdown, build checked and signed outputs; guide, reference and schema as resources (`.mcp.json`). Published as `@libka/mcp` |
| `create-libka` | The starter, `npm create libka`: an example document in English or Czech, npm scripts, a CI workflow, a `.gitignore` and a README |
| `contrast` | WCAG contrast math, pinned by tests to the same numbers as the Python build |
| `../apps/studio` | LibKa Studio, an installable local-first web app (Preact, signals, ProseMirror and CodeMirror 6): visual and source editing, switchable or side by side in step (Split); quick fixes and explained Guard findings; the command palette and changeable keys; the guided tour and the tutorial; the Inspector, the structure tree, the block palette and menus, editor preferences; live preview, Problems / Guard / History, a library of documents in IndexedDB with their images and versions, zip and folder in and out, output toggles, Word download, CS/EN, offline; built into `dist/` and served by `libka studio` (`docs/admin/studio.md`) |

```bash
npx --yes pnpm@12.8.1 install        # once
npx --yes pnpm@12.8.1 -r typecheck   # tsc in every package
npx --yes pnpm@12.8.1 -r test        # vitest in every package
```
